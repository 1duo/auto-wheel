## Durable attempt fence

`internal/moomoo/attempts.go` implements a private prerequisite for the future writer, without an HTTP transport or production caller. A new account-bound UUID intent is written and synced before returning its process-local handle. The same state mutex covers preparation, dispatch, recovery, binding and close; the lifetime deployment flock cannot be released in the middle of a synchronous dispatch. Handle copies share an atomic single-use flag. The attempt marker is atomically persisted before calling preflight or dispatch, and the bounded private response is persisted before returning an acknowledgement.

Preflight denial or panic can return `ErrNotSubmitted` only after its known-unsent result is durable. Once the dispatcher has been invoked, errors, panics, challenges, malformed/oversized responses and even a dispatcher returning that sentinel remain unknown. Failed persistence also remains unknown. Existing unresolved or orphaned records block replacement references, including after reopening state. No TTL/reset/deletion path erases uncertainty. A fresh exact broker receipt can acknowledge an attempted reference, but cannot appropriate a never-attempted preparation or prove financial reconciliation. Record counts and sizes are bounded; canonical/private file validation rejects account/terms changes, case aliases and symlinks.

Self-review corrected a recovery-clock bug before verification: the audit start and receipt-check time are retained separately, so an order update observed during the audit does not make a valid recovered acknowledgement unreadable on restart. The design review's durability, mutex/CAS and account-scope concerns were checked against the implementation. Unresolved attempts cannot expire or reset merely because time has passed; elapsed time does not prove that no order exists.

`go test ./internal/moomoo -run '^TestAttempt' -count=1` and `go test -race ./internal/moomoo -run '^(TestAttempt|TestIndependentDeploymentBinding)' -count=1` passed. These cover concurrent duplicate handles, exact dispatch terms, state lock retention, denied/cancelled/panicking preflight, unknown outcomes, close/reopen fencing, exact/missing/foreign/stale/conflicting recovery, failed acknowledgement persistence and altered/nonprivate files.
